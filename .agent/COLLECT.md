# 收词流程 / Collecting a Term

给 AI 助手看的操作手册，也给人看。目标是让「撞见一句黑话」到「一张能用的卡」这条路每次都一样走。

**先读立场**：词条靠捡不靠查——不是去检索术语表，而是你在别处跟 AI 对话时撞见一个不好理解的词，
把原话连同上下文带回来建条。所以**没有原话就不建条**。
以及不做定性评判：不给分、不判「这词是不是黑话」，只做三件事——翻译成人话、指出它其实是什么、记下在哪撞见的。

## 一条命令流

```bash
# 1. 起骨架（原话必填，脚本会拦）
npm run new -- <slug> --term "台账" --quote "我先更新一下台账" \
  --category 隐喻 --kind 代称 --source "某次架构讨论"

# 2. 填 TODO：gloss / actually / usage / decoys（判断题，见下）

# 3. 校验
npm run lint -- <slug>

# 4. 配图（可选，缺图会降级成分类通用怪）
scripts/gen-term-art.sh <slug> "<主体描述，英文一句话>"
scripts/opt-art.sh term-<slug>

# 5. 构建
npm run build
```

`npm run lint` 是**格式规范的唯一事实源**（实现在 `scripts/lint-terms.mjs`）。
它的 error 级规则同时被 `build.mjs` 复用——lint 过不了，构建也过不了。
所以不用背规则，写完跑一次就行。

## 四个判断题

脚手架能生成的只是字段位置，内容全是策展判断。按顺序想这四件事：

### 1. kind — 该不该学

把这个词换成它指代的那个东西，句子意思有没有损失？

- **没损失 → `代称`**。「AI 赋能业务」=「业务用了 AI」。学了也没用，认出来就行。
- **有损失 → `术语`**。背后确实有个概念，理解它 = 理解一件真事。

### 2. gloss — 说人话

一句话，能独立成立，**不要再出现词条本体**（用它解释它自己等于没翻译，lint 会提示）。
写完自检：一个没听过这词的人读完这句，能不能复述出这词指什么。

### 3. actually — 它其实是什么

回答「有没有旧名字 / 是不是真新东西」。
**必须出现词条本体**（term / zh / aliases 任一），页面靠它做真身高亮——这是「我靠这不就是那个谁」的认出瞬间。

### 4. usage — 遭遇战题目

考的**不是「哪个释义对」，而是「谁用对了这个词」**。这个模式是讽刺，不是教学：
AI 天天喷黑话、人类反而要去学去受教育，这件事本身就荒谬。所以别做成四个相近释义让人认真辨析。

- `right.text` —— 一句朴素、正常人会说的话。平淡无奇，这正是笑点的底（「就这？」——对，就这）。
- `wrong[].text` —— 至少 3 条，**风马牛不相及，越离谱越好**。标准玩法是把词当成完全不同的东西，
  用一本正经的语气说出来：当成食物（「我今天吃了一顿抬杠」）、动物（「路边有一只抬杠在汪汪叫」）、
  器官（「我的台账有点发炎」）、心情 / 地名 / 健身器材。
- `why` —— 每条都要有，这是真正的笑点位置。范式：先认真指认（「一种小型犬」），
  再补一刀（「你要愿意，它明天还可以是一种心情」）。

**硬约束**：4 句话每句都必须**一字不差**包含原词。同义变体（「卡住」写成「卡在」）会让测验失去唯一锚点，
lint 直接报 error。

误用的荒诞来自**认真的语气 + 完全不搭的释义**，不是来自夸张的修辞。

### 附：decoys — 备用题型

留给外部消费者的四选一猜释义，页面当前不用。恰好 3 条，标准是「看起来完全可能是对的」：
挪用邻近真实技术 / 望文生义的合理推测 / 用行业腔调生造一个像模像样的机制。
把 4 个选项给懂行的人看，他要犹豫两秒。

## 已经有这条词了

不要新建文件，**在原词条的 `sightings` 里追加一条**。同一个词的多次出没是它的活跃度证据，
不是重复数据。

## 配图

风格底座、四色调色板、验收清单在 [ART.md](../ART.md)，那是素材侧的唯一事实源。
出图不绑定任何具体文生图服务，靠环境变量 `JARGON_IMAGE_CMD` 接入你自己的工具；
不设它就走手动模式（脚本打印 prompt，你贴进任意产品生成后存到指定路径）。

主体描述写作三条：一句英文说完别写小作文；描述「是什么做的」而不是「象征什么」；给一个具体的滑稽道具。

## 页面自检

改了页面逻辑（`assets/app.js` / `app.css`）后，在浏览器打开构建产物，
把 `scripts/verify-page.js` 整段贴进 DevTools Console，返回一段 JSON 结论。
不依赖任何特定自动化工具——能「在页面里执行 JS 并取回返回值」就行。
