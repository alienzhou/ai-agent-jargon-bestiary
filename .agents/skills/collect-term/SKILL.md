# 收词 / Collect a Term

把「撞见一句黑话」变成一张能用的卡。目标是每次收录都走同一条路，产出格式一致。

## 两条立场，先认下来

1. **词条靠捡不靠查。** 不是去检索术语表，而是在真实对话里撞见了才收。
   所以**没有原话就不建条**——`npm run new` 的 `--quote` 是必填的，脚本会拦。
2. **不做定性评判。** 不给分、不判「这词是不是黑话」。只做三件事：翻译成人话、
   指出它其实是什么、记下在哪撞见的。判断留给读的人。

## 流程

```bash
# 1. 起骨架（不要手抄别的词条文件：模板会把 term 预填进造句位，避免写出同义变体）
npm run new -- <slug> --term "台账" --quote "我先更新一下台账" \
  --category 隐喻 --kind 代称 --source "某次架构讨论"

# 2. 填掉文件里的 TODO —— 见下面「四个判断题」

# 3. 校验（硬门槛，error 会让构建也失败）
npm run lint -- <slug>

# 4. 配图（可选，缺图会降级成分类通用怪，不影响构建）
scripts/gen-term-art.sh <slug> "<主体描述，英文一句话>"
scripts/opt-art.sh term-<slug>

# 5. 构建
npm run build
```

`npm run lint` 是**词条格式规范的唯一事实源**（实现在 `scripts/lint-terms.mjs`），
`build.mjs` 直接复用它的 error 级规则。所以规则不用背，写完跑一次就知道。
它分两级：`error` 阻塞构建，`warn` 只提示——值得看一眼，但不拦。

**这词已经收过了** → 不要新建文件，在原词条的 `sightings` 里追加一条。
同一个词多次出没是它的活跃度证据，不是重复数据。

## 四个判断题

脚手架只能生成字段位置，内容全是策展判断。按顺序想这四件事：

### 1. kind — 该不该学

把这个词换成它指代的那个东西，句子意思有没有损失？

- **没损失 → `代称`**。「AI 赋能业务」=「业务用了 AI」。学了也没用，认出来就行。
- **有损失 → `术语`**。背后确实有个概念，理解它 = 理解一件真事。

### 2. gloss — 说人话

一句话，能独立成立，**不要再出现词条本体**（用它解释它自己等于没翻译，lint 会提示）。
自检：一个没听过这词的人读完这句，能不能复述出这词指什么。

### 3. actually — 它其实是什么

回答「有没有旧名字 / 是不是真新东西」。
**必须出现词条本体**（term / zh / aliases 任一）——页面靠它做真身高亮，
这是「我靠这不就是那个谁」的认出瞬间。缺了 lint 报 error。

### 4. usage — 遭遇战题目

考的**不是「哪个释义对」，而是「谁用对了这个词」**。这个模式是讽刺，不是教学：
AI 天天喷黑话、人类反而要去学去受教育，这件事本身就荒谬。
所以别做成四个相近释义让人认真辨析。

- `right.text` —— 一句朴素、正常人会说的话。全场唯一一句人话，平淡无奇正是笑点的底
  （「就这？」——对，就这，剩下三个才是黑话）。
- `wrong[].text` —— 至少 3 条，**风马牛不相及，越离谱越好**。标准玩法是把词当成
  完全不同的东西，用一本正经的语气说出来：当成食物（「我今天吃了一顿抬杠」）、
  动物（「路边有一只抬杠正在汪汪叫」）、器官（「我的台账有点发炎」）、心情 / 地名 / 健身器材。
- `why` —— 每条都要有，这是真正的笑点位置。范式：先认真指认（「一种小型犬」），
  再补一刀（「你要愿意，它明天还可以是一种心情」）。

**硬约束**：4 句话每句都必须**一字不差**包含原词。同义变体（「卡住」写成「卡在」）
会让测验失去唯一锚点，lint 直接报 error。

荒诞感来自**认真的语气 + 完全不搭的释义**，不是来自夸张的修辞。

### 附：decoys — 备用题型

留给外部消费者的四选一猜释义，页面当前不用。恰好 3 条，标准是「看起来完全可能是对的」：
挪用邻近真实技术 / 望文生义的合理推测 / 用行业腔调生造一个像模像样的机制。
把 4 个选项给懂行的人看，他要犹豫两秒。笑点应该来自「正确答案居然这么朴素」，
而不是干扰项很蠢。

## 配图

风格底座、四色调色板、验收清单在 [ART.md](../../../ART.md)——素材侧唯一事实源，
别在这里另起一套。

出图不绑定任何具体文生图服务：`gen-term-art.sh` 把 `scripts/style.txt` 的风格前缀
和你的主体描述拼成完整 prompt，出图交给环境变量 `JARGON_IMAGE_CMD` 指定的命令；
不设它就走手动模式（打印 prompt，你贴进任意产品生成后存到它提示的路径）。

主体描述三条经验：一句英文说完别写小作文；描述「是什么做的」而不是「象征什么」；
给一个具体的滑稽道具（荒诞感从道具来，不从表情来）。

## 收完自检

```bash
npm run lint && npm run build
```

改过页面逻辑的话，把 `scripts/verify-page.js` 整段贴进浏览器 DevTools Console 跑一次，
返回一段 JSON 结论。不依赖特定自动化工具——能「在页面里执行 JS 并取回返回值」就行。
